# 群协作生命周期工作流设计

## 目标

将群协作从按消息时间反馈改为按交付推进。每个群都有可审计的生命周期：阶段、工作项、验收门槛、阻塞和下一步动作；群主只在流程状态发生变化时主动分发、催办或汇报。

## 范围

- 所有新群默认启用一个协作推进工作流；已有群首次打开工作流面板时创建同一默认流程，不从历史聊天推断进度。
- 支持“敏捷需求”和“产研协作”预设模板。
- 支持 AI 根据群目标、成员角色、群公告和已有工作区文件生成工作流草案；确认后才替换当前工作流。
- 在群侧栏的公告左侧提供“工作流”推进指挥台。
- 群主始终置顶，并作为群内流程编排者。

## 数据模型

新增以下 tenant/group scoped 实体：

1. `GroupWorkflow`
   - 每个群一个当前工作流，保存名称、来源（默认/预设/AI）、状态（active/paused/completed）、版本、当前阶段和总体进度。
2. `GroupWorkflowStage`
   - 有序阶段，保存名称、目标、状态、负责人、进入/完成时间、是否需要人工验收和验收门槛。
3. `GroupWorkflowItem`
   - 阶段内的可执行工作项，保存指派成员、状态、依赖、交付描述、完成证据、阻塞原因与版本。
4. `GroupWorkflowEvent`
   - 不可变事件流，记录创建、指派、开始、证据提交、阻塞、解除阻塞、验收、阶段推进和群主唤醒；每项事件包含 actor、来源、时间、唯一幂等键以及群主行动的派发状态/时间。
5. `GroupWorkflowDraft`
   - AI 生成流程的可审阅草案，保存生成请求、结构化计划、版本、失败信息和确认时间。

所有状态写入在一个事务内完成，并带版本检查；重复的 Agent 工具调用或 HTTP 重试不会重复推进阶段或重复产生群主唤醒。

## 模板与 AI 生成

默认模板为通用“协作推进”：澄清目标 → 拆解工作 → 执行交付 → 验收汇总 → 复盘。

预置模板：

- 敏捷需求：需求澄清 → 用户故事/优先级 → 排期 → 开发 → 验收 → 复盘。
- 产研协作：立项 → 方案 → 评审 → 实现 → 测试验收 → 发布复盘。

AI 生成使用平台规划模型，并接收群目标、群成员角色、公告和有限的工作区文件摘要。模型必须返回符合严格 Pydantic 合约的阶段、门槛、工作项与职责分配。生成错误或模型不可用时保留现有工作流；用户可改用预设模板。草案必须由管理员确认后才生效。

## 推进与主动协作

Agent Runtime 增加群工作流工具：认领/开始工作项、提交证据、声明或解除阻塞、请求验收、记录人工决定。群主 System Prompt 和群上下文包含当前阶段、可行动项、阻塞与责任人。

推进服务只根据结构化事件与已提交证据判断：

- 工作项全部满足自动门槛时完成阶段并激活下一阶段。
- 需要人工验收的阶段转为 `awaiting_approval`，不自动跨越。
- 出现阻塞、无负责人下一项、待验收或新阶段激活时，产生一次幂等的“群主下一步”行动事件。
- 行动通过群主 Runtime 任务触发，由群主在公开群聊中分发或汇报；相同状态不重复触发。

系统可以轮询未派发的行动事件以恢复宕机后的任务，但发送行为仅由状态变化触发，绝不按时间定时刷屏。

## 界面

群侧栏增加“工作流”页签，位于“群公告”左侧。

推进指挥台包含：

- 流程名称、来源、总体进度、当前阶段和健康状态。
- 当前阶段目标、验收门槛、负责人、已完成证据与阻塞。
- 显著的“群主下一步”行动卡。
- 按待推进/进行中/待确认/已完成分组的工作项，不按时间排序。
- 阶段轨迹和可展开事件记录。
- 管理面板：切换预设、生成 AI 草案、预览/确认草案、暂停/恢复、关键关口确认与重置。

管理员可管理流程与确认关键关口；群主可以推进工作项、记录阻塞并请求验收；普通成员只读取公开进度并更新自己被分配的工作项。

## API 与实时

群工作流 API 提供：读取当前工作流、创建/替换预设、生成/读取/确认 AI 草案、分页读取事件、更新工作项、记录证据/阻塞、确认验收和暂停/恢复。

工作流变更在事务提交后发送 group-scoped realtime 事件；群页面只增量更新受影响的阶段、工作项和行动卡。AI 生成与群主唤醒都进入现有 AI 监控记录，并带 group session 关联。

## 测试与验收

- 模板与 AI 输出合约校验。
- 事件写入、版本冲突与幂等重试。
- 自动推进与人工关口不越权。
- 群主行动只在状态变化时创建。
- 成员、群主、管理员权限。
- API 分页和实时载荷。
- 群面板、草案确认与前端构建/契约测试。

## 非目标

- 不将普通聊天文本推断为已完成交付。
- 不替换现有个人 Task 或 OKR 体系。
- 不对历史群消息回填无法验证的工作项或阶段状态。
