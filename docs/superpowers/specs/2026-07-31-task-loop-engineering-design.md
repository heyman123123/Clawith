# 任务级 Loop Engineering 设计

## 目标

在现有阶段级 DAG 之内，为所有任务类型引入可审计的“执行—验证—返工—再验证”收敛循环。任务只有验收通过后才会释放后继任务；节点和阶段不会因一次证据提交、聊天消息或文档说明而推进。

## 状态与职责

任务状态为 `ready`、`executing`、`verifying`、`rework`、`accepted`、`blocked`、`failed`。其中只有 `accepted` 表示交付已经收敛，并可满足下游依赖。

每个任务持久化执行负责人和验收负责人。两者必须是不同的群成员；创建计划时若未显式指定验收负责人，系统从群主以外的匹配专业角色中分配，无法分配则拒绝激活任务，而不是让执行者自验。

## 循环规则

1. 依赖完成的任务进入 `ready`，由执行负责人启动为 `executing`。
2. 执行负责人提交产物和结构化证据后，任务进入 `verifying`，同时派发给验收负责人。
3. 自动检查先验证代码路径、测试结果、文件产物及结构化字段；需要专业判断时由验收负责人确认。
4. 验收通过：追加本轮验收记录，状态变为 `accepted`，释放满足依赖的后继任务。
5. 验收失败：记录明确反馈、失败类别和关联证据，轮次加一，状态变为 `rework`；系统只唤醒原执行负责人返工。
6. 超过任务的最大轮次后，任务转为 `blocked` 并通知群主。群主只能协调重试、拆分未开始任务或提出结构变更；不能把任务直接标记完成。

## DAG 与决策边界

节点只有在其全部任务均为 `accepted`、节点验收条件通过时才可完成；随后才能激活下一节点。`done` 迁移为历史兼容状态，不再是新流程的完成判定。

群主处理阻塞、任务结构变更和分发；决策者将范围、外部沟通、风险、财务或发布等真正需要人类拍板的事项发送给人类管理员。人类的批准/驳回记录为决策事件，结论回流到群主和关联任务；群主与决策者均不得代替人类完成该决策。

## 数据与审计

任务增加验收负责人、循环轮次、最大轮次、最近反馈、验证开始/完成时间和收敛时间。新增任务循环记录表：每条记录保存轮次、执行/验收人、输入摘要、证据、检查结果、反馈、状态和时间。每次状态切换继续写入既有工作流事件，关联 AI 调用监控 ID。

## API 与界面

工作流图返回循环状态、执行/验收负责人、当前轮次、最大轮次、最近反馈、循环历史摘要和“已收敛/总任务”节点统计。新增启动执行、提交验证、通过验收、要求返工、显式重试接口，并严格按负责人授权。

推进面板的节点卡显示收敛进度；任务卡显示双负责人、轮次、最近反馈和验证状态。任务侧栏展示每轮产物、检查与反馈。人类决策卡显示决策者发起人、建议、输入框和批准/驳回动作。

## 错误处理与验收

- 验收人等于执行人、缺少验收人、无轮次证据、越权操作、状态越迁均返回明确业务错误。
- 重复提交用任务版本和事件幂等键去重。
- 自动检查失败不能被聊天或群主说明覆盖。
- 测试覆盖：双负责人分配、循环状态机、通过后解锁、返工不解锁、超轮次阻塞、人类决策回流、节点不可跳过和并发幂等。

成功标准是：每项任务至少经过一次可审计验证；验证不通过时只产生返工而不会推进 DAG；一个节点的全部任务均收敛后，下一节点才可被调度。
